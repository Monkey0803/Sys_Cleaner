# Swift / Rust 本地遍历实验（2026-10-19）

## 范围与方法

- 工具链：`rustc 1.99.1 (58cf8f9c3 2026-10-13)`，`cargo 1.99.1 (5f94df478 2026-08-27)`；通过官方 rustup 安装于用户目录，未使用管理员权限或修改 shell 启动文件。
- 构建：Swift 和 Rust 均为 release。每种实现分别以 1、4、8 个工作线程运行首次及随后 5 次；不同实现交替、串行运行。时间为外部墙钟时间，内存为 `/usr/bin/time -l` 的最大常驻集。首次只是本次序列的首次运行，不是严格冷缓存。
- Swift 对照按目录使用 `autoreleasepool`，与现有扫描器的临时对象释放方式一致；此前未使用时的测量已作废，不在下表。
- `Github` 原始目录中 `HM/HarmonyRss` 正由另一任务反复构建。两次无排除校验出现文件变化，因此对所有实现及生产空间扫描统一排除此 106 MB 子目录；其余内容仍从原始 `Github` 路径遍历。`Git` 完整遍历，无排除。两份原始 JSON 各包含 60 次运行记录及范围信息。
- 可控目录涵盖深层目录、符号链接、硬链接、`.Trash`、不可读目录和取消；另以临时 HFS+ 映像真实挂载第二卷，验证三种实现及现有空间扫描器均跳过跨卷文件，随后卸载并清理。云端占位文件不纳入此本地对照。

## 判断

以 4 线程 Swift 对照为基准，Rust 局部版的再次扫描中位耗时在 `Github` 缩短 **79.0%**、在 `Git` 缩短 **85.2%**；两处峰值 RSS 分别降低 **85.2%**、**53.1%**。满足事先设定的两个目录均缩短至少 25%、内存增长不超过 15%、结果一致的门槛。4 线程是本机这两处目录的最佳或近最佳配置；8 线程没有稳定收益。

Rust 共享版相对 Rust 局部版在 `Github` 为 0.427 对 0.398 秒，在 `Git` 为 0.128 对 0.125 秒。局部汇总有一定帮助，但大部分差异来自 Swift/Foundation 与 Rust 标准库遍历及元数据路径的组合，不能单凭此实验归因于语言本身。下一阶段可制作**仅空间扫描**的可关闭 Rust 原型，核对云端占位、取消、打包签名和 App 真实交互，再决定是否推广；本阶段未接入 App 或迁移六类扫描。
